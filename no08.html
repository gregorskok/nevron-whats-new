Nevron Core can now run on a ship, with no internet for weeks

Until now Nevron Core lived in the cloud. Every TV, phone and admin screen needed an internet connection to reach it. A cruise ship cannot promise that: it has internet at the dock and very little at sea. This fortnight the platform got a ship edition — a complete Nevron server that is installed on board and keeps the cabin TVs working for weeks with no connection at all.

The ship server installs with one command, makes its own passwords, and restarts by itself after a power cut. It backs itself up every night to a second disk and tests that the backup really restores. Upgrades come from a USB stick or a build store, and roll back automatically if the new version does not start cleanly. It can also run the cabin TV network itself — hand out addresses, names and the time — and keep laptops on that network away from the admin panel.

Two more pieces make it a real product. Fleet access lets Nevron and cruise-company staff on shore open a ship's own admin panel from Global Admin, with a one-time 60-second pass and no ship password. And the PMS Hub now talks to Fidelio Cruise, the guest system many ships use, so guest names and languages appear on cabin TVs and a guest is checked out only when the ship's system clearly says they have left.

A hotel used to have only two TV home screens: one for an occupied room and one for an empty room. Now staff can choose the home screen per TV, per room or per device group — and limit which channel categories each home screen offers.

AI concierge

A new answer engine, measured before it is switched on

Guest appAI conciergeIn QA

A new guest chat engine that checks every sentence before the guest sees it

The guest AI chat was rebuilt from the inside. On the test hotel it put the right item first in about 71% of answers and wrongly said “no” in 12%. The new engine reaches about 91% and 2–3%, starts typing in about two seconds, and never invents a booking or a price. It is off by default and switched on per assistant.

Money & safety

Guests' money and data, handled by one rule each

Guest appAdmin panelIn QA

An order with the guest's money on it can no longer just disappear

Eight different places could cancel or delete an order, and each decided on its own whether money was involved. Staff could delete a card-paid order and leave the guest's money on an order that no longer existed. Now one shared rule decides: an order that is card-paid, charged to the room or has a payment in progress cannot be deleted — only cancelled, which also stops the card payment.

A guest who left is checked out, even when the PMS message is lost

Now a complete resync with the PMS checks out guests it no longer lists — and an incomplete one never removes anyone.
